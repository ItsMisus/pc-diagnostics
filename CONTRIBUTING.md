# Contributing to PC Diagnostics

Thanks for helping. PC Diagnostics is an open-source (MIT) Windows app for everyone:
contributions are welcome as issues, pull requests, translations and test reports from
hardware we have not seen.

## Ground rules

These come from the project's design and are checked in review:

- **Real data only.** Never fabricate, estimate or smooth a value. If something cannot be
  read, show it as unavailable with the reason (`Unavailability`).
- **No admin for normal use**, no registry, driver, BIOS or overclock changes, no telemetry,
  works offline. The optional "Risolvi" assistant is the only feature that uses the network
  on its own, and only after explicit consent.
- **No automatic benchmarks**; one heavy benchmark at a time; Stop is always available.
- **No global health score.**
- **UI motion follows `docs/design-system.md`**: live data never animates.

## Setup

Requirements: Windows 11 x64 (Windows 10 untested), Rust stable (MSVC) with Visual Studio Build Tools,
Node.js 22+.

```sh
npm install
npm run tauri dev   # run the app
npm run check       # everything CI runs: fmt, clippy, cargo test, typecheck, vitest, build
```

If you change a type in `crates/models`, run `npm run gen:types` and commit the files in
`src/types/generated`.

## Pull requests

- Keep each PR focused; describe what changed and how you verified it (screenshots for UI).
- `npm run check` must pass.
- New user-facing text must not contain jargon in the simple view; see `docs/diagnostics-rules.md`.
- Hardware reports are valuable: if a sensor shows "n/d" on your machine but you know the
  value exists, open an issue with your CPU/GPU model, Windows version and the reason shown.

## Translations

The app ships in Italian and English. "System" in Settings follows the Windows display
language (Italian for Italian, English for everything else).

- **Interface texts** live in `src/i18n/locales/<lang>/<namespace>.ts`, one namespace per
  feature. Italian (`it`) is the reference: other languages must have exactly the same keys
  and `{placeholders}` (TypeScript and `src/i18n/i18n.test.ts` check this). Plurals use
  `<key>_one` / `<key>_other`.
- **Texts generated by the backend** (diagnostic findings, reports, benchmark labels and
  notes) are written in Rust with `models::settings::Language` (`lang.pick(it, en)`).
  Technical error messages stay in English; the UI shows a translated title per error code.
- **Adding a language**: add it to `Lang` and `LOCALE_TAGS` in `src/i18n/index.ts` and to
  `src/i18n/locales/index.ts`, copy `locales/en` and translate; then add a variant to
  `Language` / `LanguagePreference` in `crates/models/src/settings.rs` and the Rust texts.
  Open an issue first if you plan a large translation, so work is not duplicated.
